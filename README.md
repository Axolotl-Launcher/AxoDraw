# AxoDraw · 公开可验证的抽奖

抽奖最怕的就是「凭什么相信你没作弊」。AxoDraw 把随机信标、名单承诺、算法和验证结果全部公开，让参与者能够复算并发现不一致；它同时明确说明仍然存在的部署方信任边界。

> 🎯 使用地址：**<https://draw.axlmc.org>**（黑白极简风格，无需注册）

## 三步搞定一场抽奖

**1. 发起抽奖**

打开「发起抽奖」页面，填好：

- 抽奖标题；
- 截止时间（按北京时间）；
- 中奖人数；
- 参与值——一行一个，也可以直接上传 `.txt` / `.csv` 文件。

创建时会自动做人机验证，不需要注册账号。

**2. 分享链接**

创建成功后你会拿到三样东西，其中两样可以公开：

- **公开链接** —— 直接发给参与者；
- **抽奖编码**（形如 `AXO-2F0A7C16B491E3D8`）—— 在首页输入即可查询结果；
- **管理链接** —— ⚠️ **只显示一次，请立即保存**。截止前用它修改参与值，截止后 10 分钟，用它点「立即开奖」。

**3. 开奖并核对**

开奖后，中奖名单、随机数、签名、参与值承诺和摘要会公开展示。系统会自动重新获取目标轮次的 drand 信标，核验签名并复算结果；任何人也可以照着页面记录独立重算。

## 为什么可以相信它

- **随机数不来自网站**：来自 drand 公开随机信标，每 3 秒全网发布一轮。服务端固定 quicknet 的 chain hash 与公钥，并验证该轮 BLS 签名。
- **用哪一轮随机数由截止时间决定**：跟谁点、什么时候点「开奖」完全无关。
- **无偏确定性洗牌**：`deterministic-v2` 使用 HMAC-SHA-256 计数器生成独立随机块，再用拒绝采样消除取模偏差。固定输入只会得到一个结果，同时名单原始顺序不会改变每项概率。
- **公开名单承诺**：每次创建或截止前修改名单时，系统都会重算包含全部抽奖参数的 `entriesCommitment`。参与者可在截止前保存它，并在开奖后核对。
- **真实验证**：验证接口会检查目标轮次、drand 签名、名单承诺、算法版本、digest 与 winners，而不是只检查“是否存在开奖结果”。

想看逐步图解？网站上的「运行原理」页面讲得很细；也可以直接查示例抽奖 **`AXO-7K4M`**（已开奖）。

## 常见问题

| 问题 | 回答 |
|---|---|
| 需要注册或登录吗？ | 不需要，发起和查询都不需要账号。 |
| 管理链接丢了怎么办？ | 丢了就没人能改参与值、也没人能开奖。结果始终公开，但没人触发就不会产生结果，请务必保存好。 |
| 截止前还能改什么？ | 只能用管理链接改参与值。标题、截止时间、中奖人数创建后不可修改。 |
| 会自动开奖吗？ | 不会。需要持有管理链接的人在截止 10 分钟后手动点「立即开奖」。 |
| 参与值有重复怎么办？ | 创建时可勾选「自动去重」；不勾选的话，重复的每一行都算一张独立票。 |
| 按哪个时区？ | 全部按北京时间（UTC+8）。 |
| 开奖结果还能改吗？ | 正常接口不允许。开奖写入后不能再次开奖，参与值在截止后锁定；验证接口会检测记录与承诺不一致。 |

## 信任边界

`entriesCommitment` 是公开、可保存的快照哈希，但项目目前没有接入独立的外部时间戳或透明日志。因此：

- 在截止前保存了承诺的参与者，可以检测服务端后来改动名单或参数；
- 只在开奖后第一次访问页面的人，仍需信任部署方没有同时改写数据库记录和承诺时间；
- GitHub 上的源码也不能单独证明线上部署的正是同一份构建。

高价值场景应把截止前的 commitment 写入独立、只追加且带可信时间戳的公开日志。项目不会把数据库内的哈希宣传成“完全无需信任运营者”。

> 兼容性说明：旧的 `deterministic-v1` 结果仍能复算，但该版本的 LCG 洗牌存在显著顺序偏差，验证接口会把它标记为不公平；所有新抽奖只使用 `deterministic-v2`。

### deterministic-v2 精确规范

1. 按此固定键顺序执行 `JSON.stringify`：`version`（固定为 `axodraw-commitment-v1`）、`code`、`title`、`description`、`deadline`、`winnerCount`、`duplicatePolicy`、`entries`，得到 `canonicalLottery`。
2. `commitment = "sha256:" + SHA256_UTF8(canonicalLottery)`。
3. `digestHex = SHA256_UTF8(randomness + "|" + commitment + "|deterministic-v2")`。
4. 对从 `0` 开始的每个 64 位大端计数器生成 `block = HMAC_SHA256(hexToBytes(digestHex), UTF8("axodraw-deterministic-v2\0") || uint64be(counter))`，其中 `\0` 表示一个 NUL 字节。
5. Fisher–Yates 每一步令 `bound = i + 1`、`limit = 2^256 - (2^256 mod bound)`；当 `uint256be(block) >= limit` 时丢弃该块并使用下一计数器，否则 `j = uint256be(block) mod bound`，交换 `entries[i]` 与 `entries[j]`。
6. 洗牌完成后取前 `winnerCount` 项。测试目录包含固定跨实现向量和旧版兼容向量。
